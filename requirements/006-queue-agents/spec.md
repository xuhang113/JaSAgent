# 006 队列与主子代理

## 这次要改什么

现状是工作流可以单独执行，但还没有主代理队列。这次只增加调度：批量取出、按相关度合并、把工作交给子代理。主代理不调用领域工具，也不担任领域 ReAct。不改模型路由、检索和页面。

## 模块

这次新增 `jasagent-core`。它的 Maven 依赖只指向 `jasagent-api`。工作流实现不在这个模块里，调度器通过 `WorkflowEngine` 端口执行子代理任务。

## 改动地方

主队列每次最多取出 `batch-size` 条，默认 4。`sessionId` 相同的相关度是 1.0。`sessionId` 不同但 `correlationKey` 相同的相关度是 0.9。其余用目标文本的 token Jaccard。相关度达到 `merge-threshold`（默认 0.6）就合并成一条工作项。

合并后的工作项优先追加给相关且未完成的子代理。该子代理未完成数量达到 `cap`（默认 8）就新建子代理。每个子代理的队列串行。不同子代理并行。没有传入 `sessionId` 时，`sessionId` 等于 `executionId`。

提交执行在入队后就返回执行编号。工作流还堵着的时候，提交的结果已经完成，状态还不是 `SUCCEEDED`。

## 数据库

这次不改表。测试用内存记录看状态。

## 中间件

这次不启动 HTTP，也不访问外网。

## 测试要求

1. 默认 `batch-size` 是 4。
2. 一次调度最多取出 `batch-size` 条，多出来的仍留在主队列。
3. `sessionId` 相同的相关度是 1.0。
4. `correlationKey` 相同且 session 不同的相关度是 0.9。
5. 其余情况用目标文本的 token Jaccard。
6. 相关度达到 0.6 时，一个批次里的两条工作合并成一条。
7. 合并后的工作项追加到相关且未完成的子代理，而不是再新建一个。
8. 该子代理未完成数量达到 8 时，下一条相关工作新建子代理。
9. 主代理不会把自己的角色送进工作流引擎。
10. 同一个子代理上的第二个任务要等第一个结束后才开始。
11. 不同子代理的任务会同时开始。
12. 不传 `sessionId` 时，入队后的 `sessionId` 等于 `executionId`。
13. `submit` 返回时，被堵住的执行状态还不是 `SUCCEEDED`。
