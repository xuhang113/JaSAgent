# 需求 017 从 Nacos 发现并可扩缩容的 agent

**状态**: 已确认

确认记录见同目录 `review.md`。2026-11-14（Asia/Shanghai）领队、实现、测试、部署和 Hang 均已通过。016-cloud-k8s-up-stack 已整块完成。

## 这次要改什么

016 已经把一键部署和云电脑 k8s 收完。界面仍只放在 `jasagent-web`，本轮不改 sidecar。现在的问题是：默认 agent 不是动态发现出来的，Kubernetes 部署也固定两台，不会按负载自动加机器。`AgentInstance.primary()` 和 `secondary()` 写死了本机地址：`agent-18731` → `127.0.0.1:18731`，`agent-18732` → `127.0.0.1:18732`。配置空白时 `defaults()` / `parse("")` 会回到这两台。网关用 `jasagent.gateway.agents` 做静态目录，再叠加进程内存活探测。集群里 `deploy/k8s/agent.yaml` 是 `replicas: 2` 的 StatefulSet，并用两个 Service 把 `jasagent-agent-0` / `jasagent-agent-1` 分别钉在 18731 / 18732；网关环境变量 `JASAGENT_GATEWAY_AGENTS` 和官方 `scripts/k8s/probe-egress.sh` 也写死这两台。仓库里还没有 Nacos 或其它注册中心。

这次改成这几件事。

1. agent 运行时向 Nacos 注册网关能访问的地址，退出时注销。注册地址必须是网关能访问的非回环地址，不能是 `127.0.0.1`。
2. 网关只从 Nacos 发现实例。Nacos 为空或不可用时，不允许回退到静态目录或本机约定地址。
3. 继续用 MySQL 按用户做粘性；绑定实例消失时改派；若已没有可用实例，请求失败且不删除粘性行。
4. agent 按负载扩缩容。HPA 最小 2、最大 10，主指标用进行中的会话或在途请求，CPU 只作补充。实现要让 agent 暴露这一主指标。
5. 本机启动也走 Nacos，同样不得注册回环地址。实现改 `jasagent-app`、`jasagent-gateway` 和必要脚本，不改 sidecar 产品代码，实现和测试阶段不改 `deploy/k8s`。等 ATDD 全部通过后，由部署在云电脑上补 Nacos、扩缩容、网络策略、自定义指标和探测脚本，并写 `deploy.md`。

网关仍按单副本。不改 sidecar 产品行为。界面仍只放在 `jasagent-web`。验收和部署都以部署的云电脑为准，不再依赖 Hang 的 Mac。

## 改动地方

**jasagent-app**

进程启动并就绪后，向 Nacos 注册自己。注册的地址必须是网关能直接访问的主机和端口，不能是 `127.0.0.1`、`localhost` 或其它回环地址。在容器里不能把容器回环地址注册出去，要注册网关从自己的网络能连上的地址。进程退出时注销，避免网关继续把请求打到已经不存在的实例。

要暴露进行中的会话或在途请求这一主指标，供后续 HPA 使用。CPU 指标可以保留，但只作补充，不能当成唯一的扩缩容依据。本轮改到的类、常量、方法都要有注释。Nacos 的地址和认证信息只从仓库外可配置路径、环境或 Secret 读取，不写进仓库、日志、异常或响应。

**jasagent-gateway**

去掉把静态目录当作发现来源的路径。配置空白或未设置 `jasagent.gateway.agents` 时，不得再调用 `primary()`、`secondary()`、`defaults()` 或等价逻辑，回退到 `127.0.0.1:18731` 和 `127.0.0.1:18732`。网关只使用当时从 Nacos 查到的健康实例。Nacos 不可用，或查到的列表为空时，需要转发到 agent 的请求失败，不得改用静态约定实例。

粘性仍读写 MySQL 库 `jasagent` 的 `jasagent_gateway_affinity`，主键仍是租户加用户。用户已绑定的实例还在发现结果里且健康时，继续打到该实例。该实例从 Nacos 消失或不健康时，改派到其它健康的已发现实例并更新粘性。若已经没有可用实例，请求失败，且不删除粘性行。

登录会话和存活探测仍留在网关进程内。规格、配置或源码注释必须写明：本轮网关仍按单副本验收。四个内部头、令牌环境变量和去 Cookie 转发的规则保持现有约定。本轮改到的类、常量、方法都要有注释。

**scripts**

本机日常入口也必须使用 Nacos。`scripts/start.sh` 以及为完成本轮本机启动所必需的相关脚本，要拉起或连接到可配置的 Nacos，再拉起网关和 agent；agent 注册的仍须是网关能访问的非回环地址。本机仍可以在 18731、18732 监听，但这只是本机端口约定，不能再当作网关的静态发现结果。Nacos 地址和认证信息只从仓库外可配置路径或环境读取，文件缺失时以非 0 退出，说明和日志里不出现密文。相关脚本和新增的函数、常量、用法说明都要有注释。

实现提交可以按需要修正与发现对齐的脚本，但不得修改 `deploy/k8s` 下的清单。集群一键部署对 Nacos 和 HPA 的 apply，等 ATDD 全部通过后由部署一并补齐。

**deploy/k8s**

实现和测试提交不得修改这个目录。等本轮 ATDD 全部通过后，由部署在云电脑上补上 Nacos、agent 的扩缩容（HPA 最小 2、最大 10，主指标为进行中的会话或在途请求，CPU 只作补充）、自定义指标采集、以及本轮所需的网络策略。现有把 agent 固定为 2 副本、并用端口钉死 Service 指向 `jasagent-agent-0` / `jasagent-agent-1` 的做法，要改到能按上述 HPA 扩缩容，且网关不再依赖这两条静态 DNS。

官方 `scripts/k8s/probe-egress.sh` 要改成按当时发现到的实例验收，不能再只写死 agent-0 和 agent-1。现有的 egress 和 gVisor 检查范围不得缩小，整体必须 `PROBE PASSED`。然后在部署的云电脑上部署，`deploy.md` 写明环境地址、命令和集成测试结果。验收环境以这台云电脑为准，不再依赖 Hang 的 Mac。

**sidecar 产品代码**

本轮不改。
