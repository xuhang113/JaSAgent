## 这次要改什么

020 已经开放注册、一人一租户，并把控制台做成 IM 会话壳，但把「多媒体」留到后续轮次。当前 `jasagent-gateway` 是唯一入口，路径只覆盖健康检查、登录注册、控制台反代、`/api/me`、`/api/cluster`、`/admin/jaeger`，以及把其余 `/api` 粘到 agent，没有会话附件的上传、下载、列表或删除，也没有类型和大小约定。控制台仍是文本会话。024 已把网关扩到至少 2 个就绪副本，附件若只落在单个网关进程或 emptyDir，会丢，也无法跨副本读取。

这次改成这几件事。

1. 已登录用户能在自己的会话里上传、取回图片、语音和视频，并在 `jasagent-web` 的 IM 壳里展示或播放。
2. 附件由网关自己处理，不能粘到 agent。登录以 MySQL 会话为准；附件绑定租户、会话和所有者。
3. 附件优先落到已有 MySQL，不新建库；跨就绪副本可取回，删或重建网关 Pod 不丢。
4. 实现先改网关和 IM 壳并开 PR，不动 `deploy/k8s`。ATDD 通过后，再由部署开 PR 上集群（若清单需要调整）。

界面仍只用 `jasagent-web`。不改 sidecar、agentpass 和 otel 产品约定，不改运行时模型约定。本轮不把音视频或图片转给 sidecar/agent，模型看图听音放到之后的运行时轮次。Funnel / Tailscale 不在本轮，去掉隧道定为 027。验收以部署的云电脑为准。

## 改动地方

**jasagent-gateway**

附件接口的路径前缀为 `/api/sessions/{sessionId}/attachments`。上传、下载、列表、删除以及该前缀下所有子路径，都必须由网关自己处理，不能落到「其余 `/api` 粘到 agent」的默认转发。路径先规范化再匹配，不能靠 `..`、多余斜线、编码或大小写绕过前缀。

这些路径走与现有用户 `/api` 相同的登录会话校验，以 MySQL 中的会话为准，不用进程内状态。未登录的上传和下载都返回 401，且 `errorCode` 为 `AUTH`。已登录但不是该会话所有者的请求，按 020 已有约定拒绝（例如 403），不得返回附件内容。附件必须同时绑定租户、会话和所有者；仅凭附件 id，或猜测他人附件 id，不能读、改、删。租户 A 不能读、改、删租户 B 的附件。`/admin/cluster` 和 `/admin/jaeger` 不得成为跨租户取附件的旁路；025 里 admin 可见全部租户 traces 的残余不套用到附件。

类型必须使用下面的允许名单，以服务端探测到的实际内容类型为准（例如魔数），不能只看扩展名或客户端 `Content-Type`。客户端申报类型与探测结果不一致时，以探测结果为准；探测结果不在允许名单则拒绝，建议返回 415。

- 图片：`image/jpeg`、`image/png`、`image/webp`、`image/gif`
- 语音：`audio/mpeg`、`audio/mp4`、`audio/aac`、`audio/wav`、`audio/ogg`、`audio/webm`
- 视频：`video/mp4`、`video/webm`

明确排除：`image/svg+xml`、`text/html`、`application/xhtml+xml`、`application/xml`、`text/xml`，以及未列入允许名单的任何类型，包括宽泛的 `image/*`、`audio/*`、`video/*`。

大小按附件内容的原始字节计算（不含 multipart 封装开销之外多出来的部分）：图片 10 MiB，语音 20 MiB，视频 50 MiB。超过对应类型上限建议返回 413。类型或大小超限时，整请求拒绝，元数据和内容都不落库。

对象路径由服务端生成，并以租户及会话为前缀，用户提交的文件名不能决定存储路径。优先把元数据和内容落到已有 MySQL 库 `jasagent`，不新建库。不得使用单进程内存或 emptyDir 作为唯一存储。若不用 MySQL 而用共享存储，必须能被两个就绪副本同时读写，不能把两个副本挂到同一块普通 RWO 盘。

下载和播放必须携带现有登录会话 Cookie，令牌不得放进查询参数，不得提供无需登录即可访问的公开直链。下载响应必须带 `X-Content-Type-Options: nosniff`，且不得用下载响应改写 `JASAGENT_SESSION`。日志和 span 里不得写密码、令牌、Authorization 或 Cookie。

跨副本时，从一个就绪副本上传后，必须能从「不是接收上传的那一个就绪副本」取回同一份字节。该能力在实现和 ATDD 阶段就用共享的已有 MySQL（或同等可被双进程同时用的存储）验证，不依赖集群里的附件卷或 Funnel。实现提交不动 `deploy/k8s`。本轮改到的类、常量、方法都要有注释。

**jasagent-web**

IM 会话壳要让已登录用户在自己的会话里上传允许的图片、语音和视频，并展示图片、播放语音和视频。取回必须走网关附件接口和现有登录 Cookie，不能改成公开直链，也不能把公网主机名或历史 `*.ts.net` 写进前端配置。非所有者直接打开他人附件时应失败。真正的隔离仍在网关，不能只靠页面隐藏。

**jasagent-persist / jasagent-app**

仅在会话消息需要引用附件、或附件账本需要与现有 `agent_session` 对齐时接线。不另写一份会分叉的附件账本。本轮不改运行时执行模型和模型侧多模态理解，不把附件内容转给 sidecar 或 agent。

**deploy/k8s 与官方脚本**

实现和测试提交不得修改这些目录和脚本。部署阶段若需要调整清单，另开 PR，且仍须满足：不新建库；两个就绪网关副本都能读写同一份附件；不能把两个副本挂到同一块普通 RWO 盘；Ingress 仍只转到 `jasagent-gateway:18721`，不另暴露附件服务。本轮不恢复 Funnel，不把公网入口或历史主机名写成可用。官方探测仍须 `PROBE PASSED`，018–025 既有项不缩小。

**不改的模块**

不改 sidecar、agentpass 和 otel 的产品约定。不改 019 的 Cookie、受信任转发头和相对跳转约定，不改 025 的 `/admin/jaeger` 拦截约定。018 出站、021 sidecar 线程、022 运行时异步、023 通行证按租户持久化、024 网关多副本和 MySQL 持久卷的验收保持有效。
