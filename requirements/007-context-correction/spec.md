# 007 上下文与纠正 note

## 这次要改什么

现状是 ReAct 会按固定顺序组消息，但超过预算时还不会压缩，纠正 note 也还不会落在用户目录。这次补上压缩、纠正 note 存放，以及工具结果和模型记忆冲突时的处理。不改检索融合、页面和通行证策略。

## 模块

这次只改 `jasagent-core`。它仍然只依赖 `jasagent-api`。压缩通过 `ChatModel` 的 `compress` 任务完成。

## 改动地方

纠正 note 范围是 `sessionId`。字段含 `noteId`、`sessionId`、`executionId`、`createdAt`、`source`、`text`。追加时同时写入用户目录 `corrections/<sessionId>/<noteId>.json` 和执行快照。

组好的上下文估算 token 超过 `budgetTokens` 时调用压缩。规则、技能、全部纠正 note、未完成任务板、最近 4 轮不进摘要。压缩后纠正 note 仍紧挨当前用户消息。摘要走 `compress` 路由。仍然超预算时，先把旧工具结果收成一行，再把技能正文降成名称和描述。禁止删掉纠正 note、未完成任务和 `executionId`。

工具结果和模型上一句冲突时，以工具结果为准，并追加来源为 `TOOL_CONTRADICTION` 的 note。冲突的判定是：上一句助手消息里的引号片段不在工具结果里，也不在用户消息里，而工具结果非空。

token 按字符数除以 4 估算，至少为 1。

## 数据库

这次不改表。执行快照先走内存端口，调用方以后写入 `correction_note`。

## 中间件

这次不访问外网。压缩测试使用脚本化模型。

## 测试要求

1. 纠正 note 位于当前用户消息的前一条。
2. 压缩之后，纠正 note 仍是当前用户消息的前一条。
3. 压缩不会去掉规则、未完成任务板和最近 4 轮。
4. 超过预算时，模型任务是 `compress`。
5. 摘要之后仍然超过预算时，旧工具结果变成一行。
6. 收成一行后仍然超过预算时，技能正文只剩名称和描述。
7. 压缩后的 system 消息仍包含 `executionId`。
8. 追加纠正 note 后，用户目录和执行快照里都能读到同一条正文。
9. 工具结果与助手引号片段冲突时，追加 `TOOL_CONTRADICTION`，并且后续消息保留工具结果全文。
